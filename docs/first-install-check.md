# Trying Lunavect on another Mac

A short check for a new installation. Use the [public DMG](https://github.com/lovach/Lunavect/releases/download/v0.1.0/Lunavect-0.1.0-installer-2.dmg), then report what actually happened in a [bug report](https://github.com/lovach/Lunavect/issues/new/choose). No terminal commands are needed.

1. **Install.** Open the DMG, drag Lunavect to Applications and launch it. Note any Gatekeeper message, missing icon or failed launch.
2. **Connect one client.** Choose Claude or Codex. If you already use the client, check that your existing sign-in is reused. Otherwise follow the connection guide. Record the exact step if it stops.
3. **Run a small task.** Check that its title appears and changes to working, then ready. If it naturally asks for permission, check the waiting state before responding.
4. **Return to the task.** Select its row and confirm that the original client opens the exact intended session. Do not count opening only the right app as success.
5. **Check a limit.** Compare an available allowance and its reset time with the official client. Missing data should stay unavailable. Do not share your account details or quota amounts in a public report.
6. **Place a widget.** Right-click the desktop → Edit Widgets → Lunavect. Add one size, edit its content, and check whether it eventually reflects the app's data. macOS controls refresh timing; record what you observe.
7. **Quit and reopen.** Confirm that settings and connections remain usable. If convenient, check again after sleep and wake.

Include the Lunavect version, macOS version, Mac chip (Apple silicon or Intel), chosen client and whether this was a new installation or an upgrade. For a failure, include expected behavior, actual behavior and the shortest steps to reproduce it. Remove private titles, project paths and credentials from screenshots.

This is a test checklist, not a record that these checks have passed. Current evidence and remaining gaps are in [verification](verification.md).
